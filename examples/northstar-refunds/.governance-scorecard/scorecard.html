What to fix first

Fix now

These gaps let a consequential action go wrong today.

  1. 1

    Anyone can call /chat and /resume, including the endpoint that approves refunds. Outbound calls identify the agent with an X-Agent-Name header that any caller can forge.

    Identity · Verify claims at every receiving boundary Missing

    • northstar/server.py:20/chat has no auth dependency
    • northstar/server.py:25/resume (which approves refunds) has no auth dependency
    • northstar/tools.py:13unsigned X-Agent-Name header

    Fix. Require and validate a signed token (signature, issuer, audience, expiry) on /chat and /resume, and send signed tokens instead of name headers downstream.

    1. Add a FastAPI dependency in northstar/server.py that validates a JWT against the IdP's JWKS (iss, aud, exp, required claims).
    2. Apply it to both routes; /resume additionally requires a reviewer role (see Permission).
    3. Test: altered, expired, and wrong-audience tokens get 401 and never reach agent_app.invoke.

    Files: northstar/server.py

  2. 2

    Answering "no" at the approval prompt still issues the refund: the edge from confirm to tools is unconditional. send_customer_email has no approval step at all.

    Permission · Enforce policy where the side effect occurs Missing

    • northstar/agent.py:48unconditional confirm → tools edge
    • northstar/tools.py:37raw Stripe call with no approval check
    • northstar/prompts.py:5prompt-only 'be careful'

    Fix. Enforce approval inside issue_refund (and send_customer_email) so the side effect cannot run without a verified approval, and route denials away from the tool node.

    1. Add require_approval(scope="refund") in northstar/governance/approval.py and wrap the private _issue_refund_raw; the tool raises without a valid token.
    2. Replace graph.add_edge("confirm", "tools") with a conditional edge that returns to model with a denial message when not approved.
    3. Test: with approval denied, the Stripe mock is never called; calling _issue_refund_raw outside the wrapper fails a lint/AST check.

    Files: northstar/agent.py, northstar/tools.py, northstar/governance/approval.py

  3. 3

    Approval is a boolean, refund_approved, that is never reset. After one "yes", every later refund in the conversation goes through without asking, whatever the amount.

    Permission · Bind approval to the complete action Missing

    • northstar/agent.py:18boolean approval flag
    • northstar/agent.py:31skips asking once the flag is true

    Fix. Issue a signed approval token bound to a canonical hash of issue_refund + order_id + amount_pence + thread + expiry, and verify it against the actual call.

    1. Compute request_hash = sha256(canonical_json({tool, args, thread_id})) when the call is proposed.
    2. Have the approval service sign {request_hash, exp, jti}; verify signature, expiry, and hash inside require_approval.
    3. Delete refund_approved from State.
    4. Test: approve £90, then call with £900. The call must be rejected.

    Files: northstar/agent.py, northstar/governance/approval.py

  4. 4

    Uncertainty · Put the uncertainty gate before execution Missing

    • northstar/prompts.py:7prompt-only ask-when-unsure

    Fix. Add a pre-execution gate that holds any refund or email whose customer/order is not uniquely resolved and consistent across sources.

    1. Make lookup_order return all matches; add a resolve_target node between model and confirm that holds when matches ≠ 1.
    2. Re-check that the refund's order_id belongs to the resolved customer before confirm.
    3. Test: two Alex Morgans → the graph interrupts with a clarification, and Stripe is never called.

    Files: northstar/tools.py, northstar/agent.py

  5. 5

    Reliability · Inject dependency failures Missing
